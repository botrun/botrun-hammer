# v1.14.0 選單清除待補轉（Clear Pending Retranscriptions）— BDD/DAG 規劃與驗收

- **時間戳（台灣時間）**：2026-09-20 10:28:00
- **需求原句**：「我要增添選單可以清除補轉錄的能力（因為有時我就是不要這些補的）」
- **版本**：1.13.0 → **1.14.0**（新功能、向下相容 → minor）

---

## 0. 背景與問題根源（Why）

在 v1.12.0 中，波特槌引入了強大的「補轉未完成錄音（Re-transcribe）」功能：
1. 當錄音因為未登入 ADC、網路離線或取消時，紀錄會標記為 `failed` / `cancelled` / `transcribing`。
2. 為了防止未補轉的錄音被新的 30 筆歷史沖掉，v1.12.0 實作了 **FIFO 淘汰保護**（pending 項目不可被擠掉）。
3. 只要本機有任何一筆未完成錄音，每次一般錄音成功後，都會彈窗提醒：
   > 🔁 還有 N 筆錄音沒轉成功，按 F6 →「補轉 N 筆未完成錄音」即可救回
4. 同時 F6 選單首項永遠置頂：`🔁 補轉 N 筆未完成錄音…`。

### 痛點（Pain Point）
使用者不是每次失敗都想要救回！例如：
- 測試錄音、雜音、嘆氣或不小心按到 F5 錄了 1 秒
- 錄音失敗後，使用者當下已經重新講過一次並成功轉錄了，前一筆失敗的錄音已無任何保留價值
- 在舊版中，因為 FIFO 保護，這些不需要的錄音會**永遠**卡在清單中，選單與彈窗反覆提醒，使用者卻**沒有任何 UI 入口可以放棄這些補轉**。

## 1. 架構設計與原則（Design Principles）

### 原則一：狀態標記 `cleared`，不另建 queue 檔（維持 SSOT）
- 不建立 `cleared.json` 或修改儲存結構，繼續以 `history.json` 為唯一真實來源（Single Source of Truth）。
- 將 `entry.status` 由 `failed` / `cancelled` 轉為 `"cleared"`。
- `isPendingEntry(entry)` 僅認列 `PENDING_STATUS` (`{ failed = true, cancelled = true, transcribing = true }`)，因此標記為 `"cleared"` 的項目立即脫離 pending 清單。
- 脫離 pending 清單後，該筆項目自動回歸一般 FIFO 機制，在歷史累計超過 30 筆後會自然淘汰，不再永久佔位。

### 原則二：音檔絕不擅自刪除（安全第一）
- 清楚劃分「清除補轉提醒」與「刪除磁碟檔案」的界限。
- 專案鐵律：「音檔從不擅自刪除」。使用者點選清除僅表示「我現在不打算補轉這筆」，實體音檔依然安全保留在 `~/Library/Application Support/botrun-hammer/recordings/`。
- 若使用者日後反悔，從 F6 →「🎵 錄音檔案…」中依然能看見該檔案（圖示標記 `🗑️`），且透過**滑鼠右鍵**依然可執行 Process Again 重新轉錄。

### 原則三：選單自適應與零狀態不打擾（UX Adaptive Design）
根據待補轉數量自適應呈現：
1. **0 筆未完成**：不顯示補轉列，亦不顯示清除列（保持乾淨，零狀態不打擾）。
2. **1 筆未完成**：
   - 首項：`🔁 補轉 1 筆未完成錄音…`
   - 次項：`🗑️ 清除 1 筆未完成錄音`（1 鍵直達，免去子選單點擊成本）
3. **多筆未完成（≥2 筆）**：
   - 首項：`🔁 補轉 N 筆未完成錄音…`
   - 次項：`🗑️ 清除未完成錄音 (N 筆)…`（懸停展開子選單）
     - 子選單首項：`🗑️ 全部清除 (共 N 筆)`（一鍵清除全部）
     - 分隔線 `-`
     - 逐筆檔案項：`清除 <檔名>`（讓使用者可只捨棄廢音檔，保留重要音檔待補轉）

### 原則四：批次安全聯鎖（Concurrency Safety）
- 若使用者點選清除時，背景恰好正在執行批次補轉（`retranscribeState.running`），清除邏輯會：
  - 終止批次補轉 state。
  - 停止批次 supervisor timer。
  - 將項目乾淨標記為 `cleared`，避免競態條件。

## 2. BDD 規格與驗收情境

```gherkin
Feature: 清除待補轉錄音

  Scenario: S9 單筆清除待補轉
    Given 歷史紀錄中有 2 筆 failed 的錄音 A 與 B
    When 使用者呼叫 clearPending(A)
    Then pending 數量應減少 1
    And A 的狀態應變為 cleared
    And B 的狀態應維持 failed
    And 音檔 A 依然完整保留在硬碟未被刪除

  Scenario: S10 全部清除待補轉與選單呈現
    Given 歷史紀錄中有待補轉錄音
    When 使用者呼叫 clearAllPending()
    Then pending 數量應歸零
    And 所有紀錄狀態應變為 cleared
    And 實體音檔依然完整保留在硬碟
    And F6 選單在零狀態下完全不出現「補轉」與「清除」項目
    When 新增 1 筆 pending 錄音
    Then F6 選單應顯示直出項目「🗑️ 清除 1 筆未完成錄音」
    When 新增第 2 筆 pending 錄音
    Then F6 選單應顯示子選單「🗑️ 清除未完成錄音 (2 筆)…」
    And 子選單應包含「🗑️ 全部清除 (共 2 筆)」與個別檔案選項

  Scenario: S11 架構與版本號檢查
    Then Lua 核心與 CLAUDE.md 版本號皆為 1.14.0
    And clearAllPending 與 clearPendingEntry 皆已具備日誌與提示
```
