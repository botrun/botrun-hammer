# 地雷與教訓

## 1. 自動化做了，但 UI 還露按鈕 = 反向破壞信任
v1.7.4 / v1.7.9 已把 install 與 restart 自動化，但選單仍保留按鈕。使用者看到按鈕的訊號是「這件事可能要人工介入」，與我們真正想傳達的「按 F5 就好」相矛盾。**規則**：自動化落地後，必須同步把對應的手動 UI 撤掉，否則保留 = 持續向使用者暗示自動化不可靠。

## 2. 工程除錯入口不必走 UI，全域函式 + hs CLI 即可
擔心移除按鈕後除錯困難 → 用 `_G.botrunHammer = { restartDaemon = …, reinstallLwm = … }` 匯出，靠 `hs -c 'botrunHammer.restartDaemon()'` 觸發。**好處**：UI 對使用者乾淨，工程能力一個 grep 就找到。
不要為了「保留 escape hatch」就把技術細節塞給使用者看。

## 3. 選單 item 命名是產品語言的試紙
"daemon" "pip" 兩個詞洩露技術棧。即便功能本身需要保留，命名也該翻成使用者語言（例：「重新整理本機引擎」「修復本機環境」）。但若功能本就該自動，命名再美也是冗餘 — 直接刪。

## 4. 發版 SOP：版本號 + CLAUDE.md 索引 + DAG 三件一起
本專案規則：改 lua → bump VERSION（兩處）→ CLAUDE.md 當前版本同步 → docs/ 寫 DAG → CLAUDE.md 地雷索引。漏一項都會讓未來除錯失去脈絡。
